# Notices for opencode-relay

## Polygate relay template

`relay/` contains a modified copy of the relay template published by
[Polygate](https://github.com/B3hnamR/Polygate) (`relays/vercel-bun/api/relay.js`
and `relays/vercel-bun/vercel.json`).

This repository ships `relay/relay.js`, which is derived from Polygate's
`relays/vercel-bun/api/relay.js`. The deployment configuration that Polygate
ships as `relays/vercel-bun/vercel.json` is not a file here: it is generated by
`src/lib/vercel.ts`, which writes the same regions, rewrite rule and function
settings into each deployment.

Changes made in this repository:

- The Bun cipher list and the Node fallback cipher list are unchanged: OpenCode
  Free only accepts a client whose TLS handshake presents Bun's cipher suites
  in Bun's order, so that behaviour is load-bearing and was preserved verbatim.
- The relay environment variable was renamed from `POLYGATE_RELAY_TOKEN` to
  `RELAY_TOKEN`, and the host allowlist from `POLYGATE_ALLOWED_HOSTS` to
  `RELAY_ALLOWED_HOSTS`.
- The `x-relay-*` request and response headers are unchanged, so a relay
  deployed by Polygate and a relay deployed by this plugin are interchangeable.
- The relay no longer forwards to arbitrary hosts by default: `RELAY_ALLOWED_HOSTS`
  defaults to `opencode.ai`, and the `x-relay-target` header must name a host
  on that list. A `*` entry is refused unless `RELAY_ALLOW_ANY_HOST=1` is set
  as well, so a wildcard cannot be enabled by accident. A target must also use
  the default HTTPS port (443 or none) and an `x-relay-path` starting with
  `/`, so a port cannot point the relay at a different service on an allowed
  host. This matters when a relay is replaced by a Polygate deployment on a
  non-default port: that port is refused by this relay.
- An upstream failure is reported to the caller as a generic 502, and the
  detail is written to the deployment log instead of the response body.
- The deployment configuration is generated by `src/lib/vercel.ts` instead of
  being shipped as a `vercel.json` file, so that the region, the rewrite rule
  and the function settings are decided when the relay is deployed.
- The address a relay instance uses is looked up through `RELAY_TRACE_URL`,
  which defaults to the address lookup Polygate used and exists so the tests
  do not depend on that service.

## Polygate SOCKS bridge

`src/server/socks-bridge.ts` is adapted from Polygate's
`backend/socks-bridge.ts`. The MIT license text above covers this file too.

Changes made in this repository:

- The module is smaller: it starts one loopback bridge per proxy on first use,
  sweeps idle bridges, and caps the number of live bridges at 64.
- There is no pool scanner or health probing. The plugin only dials proxies the
  user added.
- The public surface is reduced to `socksBridge`, `parseSocksUrl`,
  `closeSocksBridges`, and the SOCKS4/SOCKS5 connect helpers.
- Target restrictions, the proxy credentials handling, and the HTTP CONNECT
  behavior are unchanged; the plugin's `src/server/bridge.ts` additionally
  restricts targets to `opencode.ai`.
